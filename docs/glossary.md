# Glossary

The words the code uses, what each means and the module that defines it. A
word means one thing and a thing has one word, in a docstring, a comment
and a template as much as in Python; a word the code holds to two senses
has both in its row. The words are by the part that owns them.

## The kernel layer

| word | meaning |
|---|---|
| kernel | What is launched: a template whose tag declares what it reads and writes, and whose body is C++ over one item. Declared for a case it knows its members, the bindings the body reads them through and the twin of its functor; rendered it is one unit; built it is a callable over a table and a tiling. It owns no table and no range, a call names both, and knows nothing of the order it runs in, which is a graph's. Defined in [launch/kernel.py](../peregrine/launch/kernel.py). |
| tag | The `<%pg:kernel>`, `<%pg:macro>` or `<%pg:alias>` element of a template. It runs as Python when the template renders, so Python knows every declaration before any compiler runs; a kernel tag records what it declared and captures its body, with the macros it calls expanded. A physics keeps its kernel makers under names the code calls tags, `kernels` by tag, `k["fromQ"]`: a tag's name for most, `fromQ`, `applyflux`, and for some a name no tag has, `advflux` for the flux template's `flux`, `fromeos` for the eos's own `fromQ` under the double flux. Defined in [codegen/makoutil.py](../peregrine/codegen/makoutil.py). |
| declaration | One attribute of a kernel tag: a name the body reads, with its intent, its components and the offset it is read at, `Q="in [6] at mirror"`; what it is, Python says when it makes the kernel. A name declared by a tag and a macro, or by two macros, is one declaration read at the offsets of both, the intent and the components having to agree. The case's declaration of an array is its spec, `decl_array`. Defined in [codegen/grammar.py](../peregrine/codegen/grammar.py). |
| intent | What a kernel does with a declared name, the first word of its declaration: `in`, read; `out`, written; `inout`, both. A view is const unless its intent writes. Defined in [codegen/grammar.py](../peregrine/codegen/grammar.py). |
| extern | A declaration whoever makes a kernel hands it beyond its tag's, `Kernel(provider, tpl, ..., externs={"xf": "in [3] at intface"})`, which the tag takes on beside its own: how the thing that puts a name into a kernel's text, a boundary entry's expression reading the face center or the clock, declares it without the template knowing. A tag may repeat an extern identically, never differently. Defined in [codegen/makoutil.py](../peregrine/codegen/makoutil.py). |
| binding | What a kernel's declared names stand for, given as keywords when the kernel is made: an array or a scalar of the case by name, `Kernel(tpl, Q="Q1", state="state")`, a number for a parameter. A kernel that varies with the register is made by the recipe for that register; two kernels of one template bound to arrays of one shape render the same text and share one compiled function. Every binding is checked when the kernel is declared, with no compiler in reach: an array the case does not have, a wrong shape, an offset the policy does not admit, or an array of the wrong kind or axis for the offset is refused then. Defined in [launch/kernel.py](../peregrine/launch/kernel.py). |
| policy | What a kernel runs over, one item per thread, named by the tag's `over=`: the cells, the faces of one axis, the halo cells behind the interfaces, the halo planes an exchange places, the slots of an integer list array, or the elements of an allocation. A policy knows the C++ policy whose decode turns a tile's item into the thread's item, the ranges it runs over and the words after `at` it admits; it is found by name, never by a table. Defined in [launch/policy.py](../peregrine/launch/policy.py). |
| offset | Where a declared name stands relative to the thread's own index, the words after `at`: a displacement in cells fixed in the kernel, `+I`, `-2J`, `L`, `RR`, `low`, `high`, or one only the range knows and carries, `interior`, `mirror`, `intface`, `plane`. An offset knows the C++ that reaches a member there and its reach. A subview's offset, and `pooled(array, within, offset)`, is where it starts in a memory, counted in elements. Defined in [launch/policy.py](../peregrine/launch/policy.py). |
| reach | The halo layers a declaration at an offset needs: none for the thread's own index or for a carried offset, which reads inward; a fixed offset's largest magnitude; for a face side, the cells past the interface. Defined in [launch/policy.py](../peregrine/launch/policy.py). |
| stencil | How many halo layers a kernel reads, the widest reach among its declarations' offsets. The case's halo depth is the widest stencil among the physics' kernels declared for the solution register, one at least, fixed before any block exists; a kernel declared later that reaches further, a boundary's or a plugin's, is refused. Defined in [launch/kernel.py](../peregrine/launch/kernel.py). |
| macro | Text with C++ parameters in a file of macros, `<%pg:macro>`, expanded in place in a body by `pg.expand`, the parameters replaced by the caller's words, whole words only; not a function. A macro declares the arrays its text reads as a kernel does, which the kernel expanding it takes on; its body is rendered at each expansion, as a block of its own scope or into the caller's. Defined in [codegen/render.py](../peregrine/codegen/render.py). |
| include | `<%include file="..."/>` of a file by its dotted name at the top of a template, which defines the macros in it for the template's body. A template argument selects the file, as its whole dotted name, `<%include file="${eos}"/>`, or as a piece of one, `peregrine.simulator.euler.kernels.flux.recon.${recon}`. A file included twice defines its macros again; a second file defining a macro of the same name is refused. Defined in [codegen/render.py](../peregrine/codegen/render.py). |
| alias | The `<%pg:alias name="..." file="..."/>` tag: this file's macro of that name is the one in that file, pulled from it alone, under its own name or, with `under=`, another; the alias defines the macro here as one this file wrote would be. The same tag pulls a kernel tag by its name, body captured and declarations taken on, which is how a viscous kind's file says its `preadvflux` is the Euler file's. Defined in [codegen/makoutil.py](../peregrine/codegen/makoutil.py). |
| template argument | A name every template sees, contributed by the backend, the physics and the solver and merged once for the case, a name given twice refused: the precision `fpdtype`, the species count `ns`, the solution's width `ne`, the eos file `eos`, every column a block holds under `arrays`, the physics' structs. The provider declares every kernel against them. Defined in [multiblock/solver.py](../peregrine/multiblock/solver.py). |
| kernel option | A key of `options=` on `Kernel(...)` that only that kernel's template sees, its own argument, which may not take a template argument's name: what its template branches on, a flux's reconstruction, an apply's `append`, a boundary entry's values. Defined in [codegen/render.py](../peregrine/codegen/render.py). |
| unit | The one self-contained translation unit a kernel renders to for a case: the head, the constants the body names, the functor, the check that it is the size of its twin, and the entry point named for the kernel, `pg_<name>`, which the backend's function calls; the distinct units among a case's kernels are built once each. `CellOffset.unit` is a step of n cells along one axis, the offset's word, not this. Defined in [codegen/render.py](../peregrine/codegen/render.py). |
| functor | The named struct a unit renders around a kernel's body, one per kernel: its members, a pin per entry and per item, the latter saying whether the item runs, and the operator with the bindings and the body. Python builds its argument from the members' twins and the unit asserts the two are laid out the same. Defined in [backend/base/kernels/unit.mako](../peregrine/backend/base/kernels/unit.mako). |
| member | One field of the functor, from a declared name or added by the kernel: a view of the column a declaration is bound to, the shape it is indexed in, the one index the thread stands at, a scalar of the case, a parameter of the kernel's own. A member knows its C++ declaration, its twin, what pins it per entry, how a launch fills it and the C++ a body reads it through. Defined in [codegen/members.py](../peregrine/codegen/members.py). |
| twin | The ctypes structure Python fills for a struct of the ABI or a member of the functor: `ArrInfo`, `Range`, `Tiling`, `View`, `Shape`, `Index`, `Scalar`, and the functor's own, built from its members' twins. A struct is stated once, `AbiStruct`, its fields with their C types; the twin is built from the statement and the C++ fields are rendered from it, `${abi.structs[name].cxx(indent)}` with the statements the renderer hands every template as `abi`, so the two cannot differ, and every unit asserts the compiler's size of each against the twin's. A new struct of the ABI is one statement. Defined in [backend/abi.py](../peregrine/backend/abi.py). |
| provider | What turns a kernel's template into its function for one case, `KernelProvider`: it declares a kernel by running its template once against the case's template arguments and the kernel's own columns, renders its unit, and builds the distinct units among the kernels it is given at once, each kernel handed its function from its library. It knows kernels and nothing of tags, tables, arrays or the order kernels run in. Defined in [codegen/provider.py](../peregrine/codegen/provider.py). |
| maker | What makes a kernel for the register it is given, a callable under each name of a physics' or an integrator's `kernels`, `lambda Q: Kernel(fromQ, Q=Q, state="state")`; the solver memoizes each in place, so a maker asked for a register gives the same kernel every time and one is declared and built once however many graphs launch it. A metric's maker is the block method, marked `@metric`, that makes it from the nodes. Defined in [simulator/base.py](../peregrine/simulator/base.py). |
| kind | Which class of a base a thing is. An array's kind is its range class or `Broadcast`, given where the array is declared; a boundary's, a message's, a policy's, a plugin's, a physics', an integrator's and its controller's, a backend's, a mesher's and a partitioner's are found under their base by the attribute the base matches on, `subclass_where(Base, name=...)`, never by a map or a branch on the name, so a new kind is a new subclass and nothing else changes. The attribute is `name` for all but a boundary, found by `kind`, since a boundary's `name` is the boundary name the grid gives its interfaces. Defined in [misc/subclass.py](../peregrine/misc/subclass.py). |
| role | What a name stands for, as against which thing stands there. A recipe's `Q` and `dQ` are roles the registers given at the call fill, so one recipe serves every stage; a macro file's role, a reconstruction's, a switch's, a flux function's, names its macro, so every file of one role defines the same name and an include selects among them. The registers' roles are named in [simulator/advec/simulator.py](../peregrine/simulator/advec/simulator.py). |

## The launch

| word | meaning |
|---|---|
| range | The index arithmetic of one kind of array -- the cell centers, the nodes, the faces of one axis, a plane over an interface, or an allocation flat -- on one block, whose extents and halo depth fix every iteration space over it. A named range is a list of (start, extent) in the array's own indices: `interior` the block proper, `halo(interface)` the layers behind one interface over the interface proper, `all` the interior and every halo, `shallow` the interior and the first layer of each halo, for what is read one layer in, `full` the whole allocation, for a copy or for a kernel over a list, `origin` one cell per block, for what is done once per block. A range carries the offsets only it knows, behind an interface, and cuts itself at interfaces for a launch alongside an exchange. To the launch each is a `Range` of the ABI: a start and an extent, the item count, the entry it is of and the offsets it carries. Defined in [launch/ranges.py](../peregrine/launch/ranges.py). |
| item | What one thread of a launch does, as the policy says: a cell, a face of the kernel's axis, a halo cell behind an interface, a cell of the planes an exchange places, a listed cell, or an element of an allocation. The body is called once per item, pinned to its index, `f()`, or handed the element, `f(i)`; a cell is one item and its components a loop, so to a kernel over elements a cell is as many items as its components. Defined in [launch/policy.py](../peregrine/launch/policy.py). |
| tile | As many items of one range as the backend's knob for that kind of item says, `backend.tile(kind)`, of one entry's items: what one thread does on the host, taking the tile from the parallel loop over the tiling's tiles, and one thread block on a device, one thread per item as far as the block allows, any size for a launch over elements; so a rank of many small entries and one of a few huge ones both fill the device. A tile is pinned to its entry once and to each item's index once, and a view is pinned to one entry's array per tile, since the table has many. Python cuts the tiles, since only it knows the blocks, their halo and their interfaces; the C++ policy walks a tile so that neighbouring threads touch neighbouring memory. Written in the backend's entry point, [openmp/kernels/entry.mako](../peregrine/backend/openmp/kernels/entry.mako) on the host and [device/kernels/entry.mako](../peregrine/backend/device/kernels/entry.mako) on a device. Defined in [launch/table.py](../peregrine/launch/table.py). |
| knob | A key of a backend's config section, `backend-<name>`: `tile-<kind>` for each kind of item a policy runs over, `tile-cells` and `tile-elements`, positive integers, the items a tile is, `backend.tile(kind)`; the host's `cxx`, its compiler. A backend with no case, a grid's, has none. Defined in [backend/base/backend.py](../peregrine/backend/base/backend.py). |
| entry | One row of a table: a block, or an interface of one, which answers each column with its own array or none, `tableval(name)`, an interface answering with an array of its own else with its block's. Every range is of one entry, and a launch pins its views to the entry's arrays once per tile, `pg::Entry`. An entry of a config section is one of its items under a name: a boundary's entry of `bcvals`, `BcValues` once resolved against its physics, whose values are its kernels' options; a plugin's entry of `plugins`, its section. Defined in [launch/table.py](../peregrine/launch/table.py). |
| collection | The rank's blocks, or the interfaces of its blocks of one kind, together as the launches see them: entries, derived from the blocks on first use, and the table over them, which the collection answers by the column, one array per entry as the entry itself puts it or as the collection makes for it. The block collection is the blocks themselves; a boundary collection is the interfaces of one boundary name with the physics' kind that runs there; the interior and MPI collections, the exchange's, are the interfaces met on this rank and on each other rank. Defined in [multiblock/collections/base.py](../peregrine/multiblock/collections/base.py). |
| table | A collection's entries as a launch runs over them, `ArrayTable`: their arrays' arrinfos uploaded once per name, and the tilings of the ranges launched over them, made once and kept. It makes no kernels and says nothing about the order launches run in. The launch's word: a file's dataset, a scheme's stages and tabulated data are tables in the plain sense, not the launch's. Defined in [launch/table.py](../peregrine/launch/table.py). |
| tiling | The ranges of one launch over a table's entries, cut into tiles of the backend's size; the policy's range, `Tiling` of the ABI: the range of each tile, the first tile and the items of each range, the ranges with their entries and the offsets they carry, all where the kernels run, and the items a tile is. A tiling under a key is made once and kept, named for what it covers. Defined in [launch/table.py](../peregrine/launch/table.py). |
| column | A name a table answers with one array per entry, in entry order, its arrinfos uploaded once per name and kept, since a device graph built over it holds the address. The case's columns are every bank of every array a block holds; a collection's own are the specs it adds beyond them -- a boundary kind's `outward`, the exchange's `rot`, its views and its buffers -- against which its kernels are declared. Defined in [launch/table.py](../peregrine/launch/table.py). |
| arrinfo | One array as a kernel receives it, `pg::ArrInfo` and its twin: where it is, its extents and its strides in elements, which Python works out from the device layout; the data is bytes to the backend, which never reads an element. A table uploads a column's arrinfos once per name; a view holds the pointer to them and pins its entry's data from them per tile, and a shape its extents and strides; `noarray` stands for an array an entry does not have, which a kernel never reads. Defined in [backend/abi.py](../peregrine/backend/abi.py) and rendered by [backend/base/kernels/abi.mako](../peregrine/backend/base/kernels/abi.mako). |
| spec | An array as the case declares it once, `ArraySpec`: its kind, a range class or `Broadcast`; its components, or the structs it is made of; a face array's axis; whether its halos are exchanged, and how many planes; where the 3-vector a rotational periodic turns as the halo lands starts, `vectors`, the component of a vector per cell, the solution's momentum, or the row of the tensor among an array of gradients; its banks; its element type, the case's precision or an integer. A spec answers the range the array on a block is shaped by, checks a declaration bound to it against the kind and axis the policy expects at the offset, and shapes the view. A scalar of the case binds through a `ScalarSpec`. Defined in [launch/arrays.py](../peregrine/launch/arrays.py). |
| struct | What a model declares, `Struct`: its name, its scalar fields in order, its array fields with their lengths, and the struct it extends, if one, the eos's `EosState` and the face's `FaceState` on it; what a kernel declares a local of and a macro fills, and what an array read by field is made of, the `state`. Every unit renders the case's structs, the physics' by name, with the accessor of every array made of them. Defined in [codegen/struct.py](../peregrine/codegen/struct.py). |
| accessor | What a kernel reads an array made of structs through, named for the array, `pg::State<const fpdtype>`, a field at a time, `state.T`; the slots of such an array are its structs' fields in order, and it is declared bare. A constant's accessor is the inline function a body calls it by, `MWinv(n)`, which the unit gets for the constants its text names. Defined in [launch/arrays.py](../peregrine/launch/arrays.py). |
| broadcast | The kind of one small array per entry, read whole by every thread, `Broadcast`, shaped by its components alone with no ranges: an interface's `rot`, a boundary kind's `outward` sign; declared `at broadcast`. Defined in [launch/arrays.py](../peregrine/launch/arrays.py). |
| scalar | A scalar of the case, `Scalar`: a (1,) array where the kernels run, which a kernel declares bare, `tme="in"`, and reads by its name. Its value is kept on the host in double whatever the case's precision, so a clock advanced step by step loses no time, and the copy in never waits for the kernels ahead of it, so a device graph built over it reads the current. The clock's `tme` and `dt` are the case's scalars; a scalar binds through a `ScalarSpec` and is its own column. Defined in [backend/allocation.py](../peregrine/backend/allocation.py). |
| list | An integer cell array read as a list over its allocation's slots, `at list`: a header of the count of every listed cell then each segment's count, one segment per component, then each segment's codes, a listed cell's code on the allocation's extents. A kernel over `listed` runs one thread per slot, which locates its cell as the thread's index is pinned, the cell's own bindings then as a kernel over cells has them, a slot past the count doing nothing; its one range is the allocation's slots, `full`. A float array declared at list beside it is read flat, a row per slot. Defined in [launch/policy.py](../peregrine/launch/policy.py). |
| view | What a kernel body reads an array through, `pg::View`: an array's pointer and arrinfos laid out as plain data so Python fills it, holding its pointer alone, pinned to one entry's array per tile since the table has many, and indexed in a shape pinned per entry from that array's own arrinfo, so the body indexes as if there were one block and one array, `Q.at<0, -1, 0>(cells, at)[l]`. One member per declaration, const unless written; its components are its type. On the host, `array.view()` is the array's memory itself, uncopied, for a tool with nothing in flight; a backend whose memory is not the host's has none to show. Defined in [backend/base/kernels/views.mako](../peregrine/backend/base/kernels/views.mako). |
| fnqual | What the backend gives every unit beyond the ABI's structs: the template argument `fnqual`, how it qualifies a function a kernel calls, written as `${fnqual}` before every such function, the views', the policy's, the functor's and the accessors codegen writes for a struct array and a constant lookup, so a unit never learns the spelling; and in its head `pg::atomic_add(x, v)`, x added to atomically, giving what it held, and `pg::bits<T>(x)`, the bits of x as the unsigned integer of its width. Contributed by [backend/base/backend.py](../peregrine/backend/base/backend.py) with `fpdtype`. |
| constform | The form a unit's constants take, named by the backend section's `constform` as `fnqual` is: `literal`, the values written into the code, a constexpr scalar and a function-scope static constexpr array folded under a literal index; or `memory`, a lookup defined at namespace scope, which the backend's `memqual` qualifies, `__constant__` on a device backend and `static const` on a host, the accessor reading it; every backend names `literal`. A template's own numbers, declared by `pg.constants` in the file whose macros read them, are written into the code whatever the form. Defined in [codegen/constants.py](../peregrine/codegen/constants.py), named in [backend/base/backend.py](../peregrine/backend/base/backend.py). |
| subview | An array seen through another's memory with a shape and strides of its own, nothing copied, `Subview`: how an exchange collection answers its columns -- an interface's halo planes, the interior planes it sends, the block across's planes laid out in this interface's frame -- and how a pool carves an interface's buffer out of itself. A kernel sees one as an array of its own, so the alignment of the block across is in the strides and in no kernel. Defined in [backend/allocation.py](../peregrine/backend/allocation.py). |
| launch | One run of a kernel over a table and a tiling, `(kernel, table, tiling)`: the functor filled from the table's columns and run over every item of every tile, a reduction giving its values back as a host array. A graph holds its launches in nodes, bound as they are added; `Solver.launch` runs one outside any slot, for a reduction read on the host or a one-off. Defined in [launch/kernel.py](../peregrine/launch/kernel.py). |
| reduction | A kernel that folds the items into values rather than writing arrays, `reduce="cfl max [3]"` in its tag: its body reads and writes the values by that name; the launch is the backend's fold, on the host each thread folding the tiles it took and the threads joining once, on a device the device's own fold, read on the host when it returns, so never a node of a graph; `Solver.launch` gives the values back as a host array, the fold's identity where no tile ran. The CFL speeds and the finiteness check are reductions. Written in the backend's entry point, [openmp/kernels/entry.mako](../peregrine/backend/openmp/kernels/entry.mako) and [device/kernels/entry.mako](../peregrine/backend/device/kernels/entry.mako). |
| group | Several kernels that read and write nothing of each other's, `KernelGroup`, with no order owed between them: a face flux's three kernels, one per axis, or the boundaries at one hook, whose interfaces are disjoint. A node runs its groups in order; a device graph gives a group's launches the same dependencies, so the device may run them alongside each other. Defined in [launch/kernel.py](../peregrine/launch/kernel.py). |

## The graph

| word | meaning |
|---|---|
| graph | What runs at one slot on one set of registers, the backend's: named nodes made through the verbs `add_launch`, `add_bcs`, `add_send` and `add_recv` and nothing else, each naming the nodes it follows by name and nothing else, made in the solver's words and bound to its collections by `bind` once the graph is populated. On closing the graph orders its nodes and places the host steps among them by two rules: a step that does not wait runs as early as the graph allows, one that waits as late, which puts the receives before the first node, the wait for our sends after the last, and every other step at its node. The sequence runs in order; `once` runs it outside any device graph, for a one-off. The solver makes one per slot and set of registers from its backend and hands it to the recipe that populates it. Defined in [backend/base/graph.py](../peregrine/backend/base/graph.py). |
| node | One thing a graph runs, by name, after the nodes it follows: its groups of launches, each `(kernel, table, tiling)`, and the host steps around them, empty until bound. A launch, the boundaries at one hook, the sending of a bank's halos and their landing are the nodes. Each binds itself to the solver's collections by role, `blkcoll`, `bccolls`, `interiorcoll` and `mpicolls`, every collection answering the launches of its kernels over its entries, with the solver's `spec(bank)` and `message(bank)` beside them; that is all a node knows of the solver. A grid node is a vertex of a block, the blocks section's. Defined in [backend/base/nodes.py](../peregrine/backend/base/nodes.py). |
| edge | A node's naming of a node it follows, by name, `after=`: the one dependency a graph knows. Nothing is read off a kernel's declarations; a node with no edge may run first and alongside anything, and an edge written for order alone, on a node that reads nothing of the other's, is a dependency like any other, which holds two launches apart that would contend for the device. An edge to a send or a landing also says what part of its range a launch covers; see cut. Defined in [backend/base/graph.py](../peregrine/backend/base/graph.py). |
| exchange | The sending of a bank's halos, the node `g.add_send(name, bank)`: the interior planes each interface trades packed for every other rank, and the halos met on this rank filled from the block across in one pass with no buffer between; done when the message is away. Its landing is the node `g.add_recv(name, bank)`, which follows it; between the two the message is in flight, and a launch that follows the send runs over its range cut to what the exchange filled. The halo exchange as a whole is the exchange collections, the interior and the MPI, with their pools and messages, under [multiblock/collections/exchange](../peregrine/multiblock/collections/exchange); the node is defined in [backend/base/nodes.py](../peregrine/backend/base/nodes.py) and bound, its packs, its fills and its message's steps, by the solver's `bind_send`. |
| landing | The arrival of a bank's message, the node `g.add_recv(name, bank)`: every other rank's halos unpacked from the receive buffers, the vectors turned as they land behind a rotational periodic. It follows the bank's send by construction and runs as late as the edges allow, so the message flies under everything that can run without it; its steps send our message and wait for the others' before the unpacks, and wait for our sends to be taken after. A launch that follows it covers what the message brought. Defined in [backend/base/nodes.py](../peregrine/backend/base/nodes.py) and bound by the solver's `bind_recv`. |
| cut | The part of a launch's range the nodes before it made valid, when one of them is a message's send or landing: after the send, the halos the exchange filled on this rank, `halos filled by Q`, and the boundaries' too once a hook has run before the launch by any path, `all less Q`; after the landing, what the message brought, `interior landed by grads`, the halo slabs or, of the faces, the planes on those interfaces, as deep as the array trades. A launch that follows no message covers its whole range. The launch node names the collections to cut at, the MPI ones and the boundaries', and the block collection's `launches` tiles the range less their interfaces or behind them, the ranges cutting themselves, slabs for cells and planes for faces, of which only `interior` is cut; one cut serves every bank of a family, since every bank's message brings the same halos. The partition's cut is a block split in two along an axis, a path through every block the cut plane meets, the interfaces it leaves open paired afterwards; `cuts` is its table of which base block each piece is and which slab of it, the grid file's `cuts` dataset. |
| sink | The names of the nodes of a graph nothing follows yet, `g.sinks()`: what a node added after everything so far follows, which is where a physics' plugin's launches go in a slot. Defined in [backend/base/graph.py](../peregrine/backend/base/graph.py). |
| host step | A callable a node runs before or after its launches, eager or waiting on the host, given by the binder: a send's receives posted before it and its copy out after, a landing's send and receive before it and the wait for our sends after. The steps carry their own device ordering, so an edge into the node means after what it follows is submitted; a device builds the nodes between two steps as one device graph. Defined in [backend/base/nodes.py](../peregrine/backend/base/nodes.py). |
| recipe | A method of the physics or the integrator that populates a slot's graph for the registers it is given, named for the slot with the suffix `_graph`, which is how the solver finds it: the physics' `prestep_graph`, `poststep_graph`, `initialize_graph`, `prerhs_graph`, `begin_dQ_graph`, `rhs_graph` and `postrhs_graph`, the integrator's `advance_graph`; a method a recipe calls to add its part is named the same way, the chemistry's `begin_dQ_graph`. The base physics answers every slot, four with nothing, so a physics writes only the recipes it has something for. A recipe makes the kernels for its registers from the physics' makers by name, `k["fromQ"](Q)`, and is the schedule: what it does not order, the graph does not order. The physics' are declared in [simulator/base.py](../peregrine/simulator/base.py). |

## The step

| word | meaning |
|---|---|
| step | One step of the run, `mb.step(dt)`: the step size set on the clock, `prestep`, the integrator's stages, each the right-hand side of its registers, the clock at its time and its advance, then `poststep`, and the count and the time moved on; the controller sizes each step of `mb.run()`. A message's host steps are its methods a graph runs around its launches, at which the graph is cut into pieces; an offset's step is its displacement in cells along an axis. Defined in [multiblock/solver.py](../peregrine/multiblock/solver.py). |
| register | One bank of the solution, an array of its shape on every block: `Q`, which holds the solution between steps, then `Q1`, `Q2`, ..., as many as the integrator's `nregs` asks, `mb.regs` their names. A scheme is register algebra, a stage readying one register, taking its right-hand side into another and advancing the registers into the next stage's, copying nothing; a recipe takes registers by role, `rhs(Q="Q1", dQ="Q2")`, and the kernels are made for the register given. Declared in [multiblock/solver.py](../peregrine/multiblock/solver.py). |
| stage | One of the integrator's moves within a step, its registers a `StageRegisters`: it reads the solution from `Q`, takes its right-hand side into `dQ` and leaves the solution in `Qout`, the registers combined as the scheme's weights say, with the clock at the time the state it produces is at. The solver fills the slots over registers once per set the stages step through. Defined in [integrators/base.py](../peregrine/integrators/base.py). |
| slot | One of the named places a run's launches go, in the order a step runs them: `prestep` on the solution and the derivative; then per stage `prerhs` on the stage's register, alone and with the derivative begun into, `begin_dQ`, `rhs`, `advance` and `postrhs` on what it wrote; then `poststep`; and `initialize` once when a state is set. Each is a graph the physics' or the integrator's recipe fills for the registers given and the solver runs, every kernel known before the first step; a physics' plugin adds launches to a slot after the physics', `begin_dQ` apart. Of a list, an allocation or a vector, a slot is one position: `SlotRange` the slots of one block's allocation flat, which a kernel over a list's slots or an allocation's elements runs over under the name `full`, a listed thread keeping its slot beside its cell in `pg::Index`; the slots of an array made of structs are its fields in order, and the primitive vector's are its variables, which the physics' `IoVars` names. Defined in [multiblock/solver.py](../peregrine/multiblock/solver.py). |
| hook | A point in a slot's recipe where the boundaries run on a register, `g.add_bcs(hook, Q)`: `preadvflux`, before the advective flux, over the halo cells behind a kind's interfaces; `postflux`, after the fluxes, over the faces on them, for a kind whose data fix the flux through its faces; a diffused physics adds `pregrads` and `postgrads` around the gradients. A kind's template holds one kernel tag per hook, named by it, and the kind makes the kernels at each hook, one per axis, bound to what the hook reads; a hook no kind of the case fills launches nothing, and one the physics does not have is refused. Defined in [simulator/bcs.py](../peregrine/simulator/bcs.py). |
| readying | What makes a register fit for its right-hand side, the slot `prerhs` run on it: what the boundaries hold that moves with time put at the clock's time, the register's halos exchanged and what the physics derives from it made over the halos as the exchange fills them and again over what the message brings, the boundaries at `preadvflux`, and the derivative `dQ` begun meanwhile when one is named. A readying is at the clock as it stands, the step size included, and stands for the next right-hand side taken of its register, `mb.readied` holding each with the derivative begun into it, `None` for nothing; the right-hand side spends what was begun, a stage's advance drops the readying of the register it wrote, and a register written by hand is readied whole by `postrhs`, nothing begun. Defined in [multiblock/solver.py](../peregrine/multiblock/solver.py). |
| clock | The run's step count, time and step size, `nrt`, `tme` and `dt` on the solver, the last two scalars of the case held where the kernels run: a kernel declares one bare, `tme="in"`, and the host reads it as `mb.tme.get()`. Between steps `tme` is the step's time; within one, the time the state the next stage reads is at. The step is set, `mb.dt.set(dt)`, before a right-hand side taken outside a step, since what begins the derivative is sized by it. Defined in [multiblock/solver.py](../peregrine/multiblock/solver.py). |

## The case

| word | meaning |
|---|---|
| physics | What a solver simulates, the simulator: the class is `BaseSimulator`, named by the config's `simulation.simulator`, `sim` on the solver. A spec the solver interrogates for what it needs declared, block arrays, kernel makers by name, kinds of boundary, structs and template arguments, what it puts in each slot, and its initial state; it owns no solver, arrays, state or graphs. The bases are an advected solution and a diffused one, the systems the equations of a fluid built on them, `euler` and `navier-stokes` with the double flux's `euler-df` and `navier-stokes-df`, and the physics of the gas is the mixture beside them. Defined in [simulator/base.py](../peregrine/simulator/base.py). |
| integrator | What moves a solver through time, `BaseIntegrator`, named by the config's `time-integration.integrator`, `integ` on the solver: a scheme over the solution's registers, saying how many it needs, `nregs`, and working them by index, its recipes `stageregs` and `advance(g, regs, n)` taking the registers and its `step(solver, dt)` the solver; it holds nothing of the solver it steps and names no array. The schemes are Runge-Kutta, a step a fixed list of stages. Defined in [integrators/base.py](../peregrine/integrators/base.py). |
| controller | What sizes each step, the integrator's, named by the config's `simulation.controller`, `stepsize(solver)`: `fixed`, every step the config's `dt`; `cfl`, each step as large as the config's `cfl` allows over the largest combined speed on any rank, up to `dt-max` and no further than the next time a plugin acts at. Defined in [integrators/controllers.py](../peregrine/integrators/controllers.py). |
| plugin | What a run does alongside the stepping, made from its config section by the section's name and owned by the part it hooks into, which claims the plugins of its level from the config's `plugins` section, an entry no part takes refused. A solver's acts on the solver after a step it is due on, as often as its cadence says, every so many steps or every so much time, and once more at the end; a physics' adds launches to a slot after the physics', `begin_dQ` apart, and says which physics it is valid for as a pattern their names match whole. Defined in [plugins/base.py](../peregrine/plugins/base.py). |
| level | A plugin's level is the part that owns it, the solver or the physics, which claims the plugins of its level from the config's `plugins` section. Defined in [plugins/base.py](../peregrine/plugins/base.py). |
| mesh | What fills a multiblock's blocks, which starts with none, `mesh.fill(mb)`: a mesher, which describes a shape and how finely to cut it up and makes every block, its coordinates and the connectivity, the blocks laid out as a lattice whatever the shape; or a grid reader, the grid file with the partition it took, every block or this rank's share, which the results name. A partition is the placement of a grid's blocks on ranks, the partitioner cutting the grid down until its pieces fit and placing them, carried by the grid file as `partitions/<ranks>x<ranks per node>`. Defined in [multiblock/base.py](../peregrine/multiblock/base.py). |
| primitive vector | The state a case starts from and a result holds, `q` on every block, `nprims` wide. The physics' map of its results, its `IoVars`, says what the vector's slots are, each name with the value a result lacking it starts at or `None` for one it must hold, what a result writes, and the vectors among them; for a fluid `p`, `u`, `v`, `w`, `T` and the mass fraction of every carried species. The solution is made from it by the physics' `fromprims` over every cell and the vector released; `set_prims` sets it from host arrays, and a boundary's entry is resolved against it. Defined in [multiblock/restart.py](../peregrine/multiblock/restart.py). |
| state | Two things. The case's state is what its blocks hold between steps, set from the primitive vector a fresh case or a result gives, or by `set_prims`, and then settled: `initialize` is the slot that makes a state just set consistent, nothing for most, under the double flux the state made consistent by the eos once and every cell's tangent plane frozen at it. The `state` array is what the eos derives beside the solution at every cell, made of structs read by field, the eos's `EosState` and under the double flux the tangent plane, written from the solution by `fromQ` and from the primitive vector by `fromprims`. Defined in [simulator/euler/simulator.py](../peregrine/simulator/euler/simulator.py). |

## The blocks and the halo

| word | meaning |
|---|---|
| multiblock | The connectivity of a case, its blocks and how their interfaces join, with the one spec of every array its blocks hold, `decl_array`, in layers each adding what it has: `BaseMultiBlock` the connectivity, `Grid` the coordinates, the metrics and the node halos, `Restart` the state, `Solver` everything compiled and runnable. It starts with no blocks; whoever knows how many there are, a mesher, a grid reader, a partition, adds them. Defined in [multiblock/base.py](../peregrine/multiblock/base.py). |
| block | One structured block of the grid: its number `nblki`, its extents in nodes `ni, nj, nk` and its interfaces, one at each end of each axis, each saying what is across it. A block is a record that knows itself alone, layered as the multiblock is; every array the multiblock declares is an attribute of the block named for it, `blk.Q`, allocated with its halo when the extents are set, and a solver block puts its arrays in the tables by name. Defined in [multiblock/block/base.py](../peregrine/multiblock/block/base.py). |
| interface | Where a block meets another block or the outside, one at each end of each of its axes, behind which its halo lies, numbered by `nface`, 1 to 6, the low and high ends of i, then of j, then of k, and the one it meets by `nbrnface`: the record the grid file keeps of what is across it, a block by number and orientation, a periodic's transform, a boundary's name, and the alignment that follows from it. It is layered as the block is, `BaseInterface` the connectivity, `GridInterface` the halo planes of a block array, `SolverInterface` its block, the shape of a plane over itself and arrays of its own, which it allocates and answers the table with. The word is not swapped with face. Defined in [multiblock/interface/base.py](../peregrine/multiblock/interface/base.py). |
| face | A face between two cells, of one axis: as many as the nodes along it and the cells across it, indexed like the cell to its right, so a cell's low face is indexed like the cell and its high face one past it; a face array, `iS`, `iF`, has an axis. The plane of faces lying on an interface is what a boundary's kernels at `postflux` run over. Defined in [launch/ranges.py](../peregrine/launch/ranges.py). |
| node | Of the grid, a vertex of a block: `nodes` the array of them, every block's coordinates, exchanged; `NodeRange` their range, the extents `ni, nj, nk` counted in them, one more than the cells along each axis; the plane on an interface is held by both blocks across it, so an exchange of nodes starts one plane in. The node halo is extrapolated from the block alone, interfaces first, then the edges between them, then the corners, and overwritten by the exchange behind a connected interface, a periodic's moved by its transform. A graph's node is the graph section's. Defined in [multiblock/grid.py](../peregrine/multiblock/grid.py). |
| boundary | An interface that meets the outside, `nbr` `None`, which the grid names and the case's `bcvals` says what it is, by kind; an interface with a neighbor is interior and one with a transform periodic, and neither is a boundary. A boundary the grid left unnamed, or named for nothing in `bcvals`, is refused when the solver is built. Read off an interface's connectivity as its `intkind` in [multiblock/interface/base.py](../peregrine/multiblock/interface/base.py). |
| periodic | An interface whose halo comes from a partner its nodes do not sit on: a halo arriving through it lands at R p + t, its transform `rot` and `xlate`, each kind naming its own, `periodic-xlate` moved, `periodic-rot` turned, the rotational one turning the vectors of an exchanged array as they land and the node halo by the same; found among the joined interfaces by `find_periodics`, from the two node planes, and stored in the grid file. Defined in [multiblock/interface/base.py](../peregrine/multiblock/interface/base.py). |
| orientation | The three characters an interface holds for the block across, `orient`, GridPro's notation: for each of our axes, which of the neighbor's axes it runs along, 1 to 3, and whether against it, 4 to 6, `123` an aligned neighbor. The character of the interface's own axis names the neighbor's axis and so its `nbrnface`; the other two say how its plane lies against ours, which the exchange lays out in the strides of its views. Defined in [multiblock/interface/base.py](../peregrine/multiblock/interface/base.py). |
| halo | The layers of cells behind each interface of a block, `ng` deep, which every block array carries around the block proper: across a connected interface the block across's interior planes, which the exchange places; behind a boundary what its kind writes. The depth is the widest stencil among the physics' kernels, one at least, fixed before any block exists; a grid without a physics has none unless made `Grid(ng=...)`. A halo is a slab over the interface proper, its layers counted outward from the interface, layer 0 nearest it. No range generates a halo edge or corner cell and no kernel reads or writes one; the host extrapolates the node halo into them and pads a state read in over the interior into every halo plane, edges and corners included, so every halo cell has metrics, infinities where it has no volume, which nothing reads. The word is halo, not ghost. The depth is sized in [multiblock/solver.py](../peregrine/multiblock/solver.py); the ranges over a halo are defined in [launch/ranges.py](../peregrine/launch/ranges.py). |
| layer | Two things. Of the multiblock, the block and the interface, one of the classes each is built up through, each adding what it has to the one below, `BaseMultiBlock`, `Grid`, `Restart`, `Solver`, the block's and the interface's named the same. Of a halo, one plane of cells behind an interface, counted outward from it, layer 0 nearest it, `halolayer`; a halo kernel runs over the halo cells of every layer, carrying its offsets layer for layer. Defined in [multiblock/base.py](../peregrine/multiblock/base.py). |
| plane | One index plane of a block array normal to an interface, `plane(index)` of the interface: the whole plane of the allocation, its in-plane halo included, which the node halo is generated and moved through, its parts the interface proper, the edges around it and the corners. Over the interface proper: a halo layer and an interior plane the exchange sends, the planes an interface trades, as many as the array's spec says, laid out layer first in the interface's own frame; the plane of faces lying on an interface, `FaceRange.plane`, and `faceplane`, the same of a face array on the host; and an array of an interface's own, the kind `InterfacePlaneRange`, extent one along the axis and the in-plane cells across, no halo, which a halo kernel reaches at the carried offset `plane`. The index plane is defined in [multiblock/interface/base.py](../peregrine/multiblock/interface/base.py), the planes over the interface proper in [launch/ranges.py](../peregrine/launch/ranges.py). |
| tangent plane | The double flux's: the plane tangent to the eos's internal energy in pressure, density and the partial densities of the species at a cell's state, rho e as theta p plus eps rho plus the sum over species of zeta_n rho Y_n plus kappa, which every cell freezes once a step and advances its energy in, its pressure between freezes the plane's; the energy a face carries is written once in each cell's plane. Its fields sit on the state beside the eos's, the struct `TangentPlane`. The plane is `real-gas-df`'s, the eos that declares its fields and the macros that work it, and `euler-df` and `navier-stokes-df` freeze it; any other eos under them is refused. The double flux's code shortens it to the plane: every cell's plane frozen, the plane's fields, `planefields`. Defined in [simulator/mixture/eos/realgasdf/model.py](../peregrine/simulator/mixture/eos/realgasdf/model.py). |
| mirror | The carried offset of a halo kernel that reads the halo cell's image in the block, layer for layer: the image of halo layer l is interior cell l, `mirror`, and `mirror1` the next cell in; a block thinner than that reaches gives its deepest cell instead, so a one-cell slab between walls reflects its one cell into every layer. A wall's halo is its image reflected about the wall, layer for layer. Beside it stand `interior`, the first cell inward whatever the layer, and `intface`, the face lying on the interface. A message's mirror is the pinned host copy of a pool the `hoststaged` kind travels through. Defined in [launch/policy.py](../peregrine/launch/policy.py). |
| proper | The block proper is its interior, what is not halo, whose extents a range kind counts in its own units; the interface proper is the plane of the interface without the in-plane halo around it, which every halo slab, the plane of faces on an interface and the shape of an interface's own arrays are over, the halo's edges and corners lying outside it. Defined in [launch/ranges.py](../peregrine/launch/ranges.py). |
| across | The block across an interface is the one it meets, `nbr` by number, on this rank or another, `offrank`; the interface across is the one of that block the two share, `nbrnface`, which the multiblock gives when the block is held here. What is across an interface is what the grid file records of it. Defined in [multiblock/interface/base.py](../peregrine/multiblock/interface/base.py). |
| frame | The axis order and direction a plane is laid out in. An interface's own frame is its block's, the layer first then the plane's two axes in axis order; the block across's frame is that block's, whose plane axes each run along one of ours, forward or against, as the orientation says. The exchange lays out every view it answers in the interface's own frame, so a thread's cell in one is its cell in the other; a send buffer is in our frame, and a received buffer arrives in the sender's and is seen in ours. Defined in [multiblock/collections/exchange/collection.py](../peregrine/multiblock/collections/exchange/collection.py). |
| carried | Three things. Of an offset, one the range carries, which the kernel names by its key and reaches as `atoffset<key>()`, since only the range knows which way is inward; of a block, the arrays a cut, a merge or a reorient carries with it, `carried`, the nodes, the rest derived again; of a species, one the solution carries a row for, all but the last, which is what the others leave. Defined in [launch/policy.py](../peregrine/launch/policy.py). |
| bank | One block array under a declared array's name: the array itself, or a register named after it, `Q`, `Q1`, `Q2`, `spec.banks`. An array with several banks is a family, declared once, each bank an array of its own on every block, and the case's columns are every bank of every family. An exchange is of one bank; its message and the halos it brings are the family's, the same for every bank. Defined in [launch/arrays.py](../peregrine/launch/arrays.py). |
| family | An exchanged array with its banks: declared once, with one message and one pool each way for all its banks and one cut of a range for all, since every bank's message brings the same halos; a message is tagged by the family's place among the exchanged, `xchgarrays`, the same on every rank. Defined in [multiblock/solver.py](../peregrine/multiblock/solver.py). |
| message | What carries an exchanged family's halos between ranks, one per other rank each way, of the kind the config's `halo-exchange.kind` names: the host steps a graph places among its nodes, `expect`, `copy_out`, `send`, `recv` and `sent`. A message travels through a send pool and a receive pool, one each per family; the kinds say through what: `hoststaged`, pinned host mirrors of the pools, which MPI touches, one copy of the whole send pool out and one copy in per rank as its message lands; `device`, the pools themselves where the kernels read them, which on a device needs a GPU-aware MPI. A kind's copies are the backend's asynchronous ones, `async_pull` and `async_push`, beside its kernels, and who waits for whom is asked of the backend alone: `await_copies`, the host for the copies; `copies_await_kernels`; `kernels_await_copies`. Defined in [multiblock/collections/exchange/message/base.py](../peregrine/multiblock/collections/exchange/message/base.py). |
| pool | One device array holding, for one exchanged family and one direction, every other rank's buffers, rank by rank, so each rank's part is one contiguous message and is copied on its own as its message lands; each interface's buffer is carved out of it into its MPI collection's columns, `sbuf` and `rbuf`, which the pack and unpack kernels write and read, a received buffer seen in our frame. Defined in [multiblock/collections/exchange/pool.py](../peregrine/multiblock/collections/exchange/pool.py). |
| part | Of a pool, one rank's buffers in it, contiguous, one message, copied on its own as the message lands; of a cut, one piece of a named range, what lies behind the interfaces or the range less it; of a plugin, the part of the code that owns it, the solver or the physics, which claims it from the config. Defined in [multiblock/collections/exchange/pool.py](../peregrine/multiblock/collections/exchange/pool.py). |
| move | One of the exchange collections' launches on a bank over its interfaces: `fill`, the interior collection's, the block across's planes into the halo; `pack`, the MPI collection's, an interface's interior planes into its send buffer; `unpack`, its receive buffer into the halo. Each is a group of one launch, a range per interface over the planes it trades, a landing in one group over the interfaces whose vectors turn and one over the rest. Defined in [multiblock/collections/exchange/collection.py](../peregrine/multiblock/collections/exchange/collection.py). |
| place | What every kernel of the exchange does, of the one template `place.mako`: one array's halo planes placed from one view into another over the planes' own indices, the two views the same shape and laid out so the thread's cell in one is its cell in the other, whatever the alignment of the block across, the vectors turned by the interface's rot as they land behind a rotational periodic. Defined in [multiblock/collections/exchange/kernels/place.mako](../peregrine/multiblock/collections/exchange/kernels/place.mako). |
| metric | An array a block makes from its nodes, each by its own method marked `@metric` with the kind and components the grid declares it with: the face centers and area vectors of each axis, the inverse volume, the cell lengths, the inverse jacobian; made with the cell centers once the mesh is filled and the node halo unified, before the boundaries' values, which may be made from them. Defined in [multiblock/block/grid.py](../peregrine/multiblock/block/grid.py). |
